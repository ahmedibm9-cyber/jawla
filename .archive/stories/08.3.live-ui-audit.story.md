## Story

**As the** business owner,
**I want** a screenshot-verified pass over every page of every account type at real device sizes,
**so that** the "things look broken" reports are turned into a concrete, fixable list instead of a feeling.

---

## Context (from the investigation — do not rediscover)

- Static code audit found **no remaining layout hazards**: card-based rep views, `x-ds.*` components adopted (49 usages / 14 views), modals sized `calc(100vw - 32px)`, no wide fixed widths, prior sweep commit `b5860ee` closed the issue-#7 findings list. So the remaining visual defects — if any — only show when rendered: long Arabic strings, dynamic states, real viewport widths, Filament admin tables.
- Owner devices are unknown → test the full range.

## Audit Matrix (all cells)

- **Roles:** rep (all 24 `/app` screens), admin/Filament (every resource list + form + the dashboard), and each other role (finance, sales_manager, system_viewer) at least for their landing + alarm screens.
- **Widths:** 320, 375, 768, 1024, 1440 px.
- **Locales:** AR (RTL) and EN (LTR) — every cell in both.
- **States per screen:** loaded-with-data, empty (`x-ds.empty` visible?), loading (skeleton visible?), error, and long-content (customer/product names > 40 chars, badge `99+`, totals ≥ 1,000,000).

## Acceptance Criteria

1. Every matrix cell visited in a real browser (agent-browser/Playwright) with a screenshot saved per cell under `bmad-output/ui-audit-2026-07/`.
2. Zero horizontal page scroll at 320 px on every rep screen; Filament tables may scroll **inside** their own container only.
3. Every finding filed with screenshot + file:line + severity into `bmad-output/investigation-race-conditions-and-rep-reliability-2026-07-20.md` via Update intent (new evidence items), and a follow-up fix story drafted if ≥ 1 High-severity finding exists.
4. Explicit pass/fail verdict recorded for the CLAUDE.md NFR "RTL Arabic + LTR English work everywhere".

## Dev Notes

- This story intentionally ships no code. Do not "quick-fix while auditing" — file findings, keep the audit unbiased and complete.
- Seed data must include worst-case strings (very long Arabic names, max-digit money) before screenshotting; otherwise the audit proves nothing about overflow.

## Story

**As a** sales rep,
**I want** a bell with an unread badge on every rep page and a notifications list,
**so that** I learn quotation, customer-approval, and complaint outcomes without calling my manager.

---

## Context (from the investigation — do not rediscover)

- **Vehicle decision:** Laravel **database notifications**, NOT the alarm domain. `User` already has `Notifiable` (User.php:22); the `notifications` table migration is missing — create it first (`php artisan make:notifications-table`). No new packages. Alarms (`AlarmService`) are admin-role broadcasts and stay untouched.
- **The rep layout has no header.** `layouts/app.blade.php` renders `<main>{!! $slot !!}</main>` only. Add a small persistent header strip to the layout for the bell so it appears on all 13 rep pages.
- **Quotation lifecycle is `requested → priced → confirmed/cancelled`** — not "approved/rejected" as the issue text says. Notify on **priced** and **cancelled**. Rep confirmation continues to happen in `QuotationFlow` (line 79) — do not change that flow.

## Acceptance Criteria

1. **Migration + classes:** stock `notifications` table migration; four Notification classes (database channel) with bilingual payload (`title_ar/title_en`, `body_ar/body_en`, `severity`, deep-link route).
2. **Exactly-one delivery:** each live event (quotation priced, quotation cancelled, customer approved, customer rejected incl. reason, complaint resolved) produces exactly one notification to the correct rep of the **same company**. Feature tests cover the failure paths: no cross-company delivery, no delivery to other reps, no duplicate on retry, no notification when the wrapping transaction rolls back.
3. **Bell + badge:** bell button in a new layout header strip on every rep page; unread count with `aria-live="polite"`; red dot only for critical events (assumed: customer rejected, quotation cancelled — confirm with owner, Open Q3); `<button>` with `aria-label`, RTL-correct.
4. **Notifications page:** `/app/notifications` inside the existing `ensure.rep` group; paginated; mark-read on open persists (verify by reload); uses `x-ds-empty` / `x-ds-skeleton` states (do NOT repeat gap G1); bilingual AR/EN.
5. **Translations:** all strings in `lang/en/app.php` + `lang/ar/app.php`.
6. **Out-of-stock resolved:** Notification class exists and is unit-tested in isolation; wiring deferred to issue #2 with a code comment referencing it.
7. Feature tests for generation, scoping, and read state pass; existing suite stays green.

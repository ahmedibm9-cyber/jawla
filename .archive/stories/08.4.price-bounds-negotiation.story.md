## Story

**As a** sales manager,
**I want** to set a catalog price plus a minimum and maximum price per product, with reps only able to negotiate inside that range,
**so that** a rep can never sell at 1 EGP what costs 500 — and never gouge above the ceiling either.

---

## Context (from the investigation — do not rediscover)

- Owner decision (2026-07-20): _"sales manager sets a catalog price and a minimum and maximum price, and rep negotiates."_ This replaces today's fully-open pricing.
- Today: `SalesFlow::updatePrice()` (SalesFlow.php:129-137) accepts any price ≥ 0; nothing server-side validates it; `PricingService` exists but is not consulted by the sale flow.
- The enforcement point MUST be the service layer (`InvoiceService::create()` validating each line's `unit_price`), not the Livewire UI — CLAUDE.md: never rely on UI alone.

## Acceptance Criteria

1. **Schema:** `products` gains `min_price` and `max_price` (nullable decimals; null = bound not set → falls back to catalog price as both bounds? No — null bound means "no limit on that side", explicit and documented). Migration + `$fillable` + factory updates.
2. **Manager UI:** Filament product form exposes catalog/min/max with validation `min_price ≤ price ≤ max_price`; only roles with product-edit permission see them.
3. **Server enforcement:** `InvoiceService::create()` (and the sync-replay path — same service, so it's covered) rejects any line whose `unit_price` is outside `[min_price, max_price]` with a bilingual error naming the product and the allowed range. Proforma/quotation creation gets the same guard.
4. **Rep UX:** the sale cart shows the allowed range per line; out-of-range input is flagged inline before submit (client hint only — server remains the authority).
5. **Tests:** in-range passes; below-min and above-max rejected (both online and via `/app/sync` replay); products with null bounds behave as documented; suite green.

## Dev Notes

- Keep the guard in the service so the offline sync path is automatically covered — do not duplicate the check in the Livewire component beyond the UX hint.
- "Manager approval for below-min" was offered to the owner but NOT chosen — hard-reject below min. Do not build an approval flow.
- Bilingual strings in `lang/en/app.php` + `lang/ar/app.php`.

# Governance, Privacy, Observability, DevOps, and Operations Audit

**Audit date:** 2026-07-22  
**Method:** Static repository review only. No application, test, build, browser, scanner, network, database, Railway, or deployment command was run.  
**Scope:** Checklist sections 2, 14, 15, 16, 17.10, 18, 19, and the section 23 go/no-go questions.  
**Decision:** **NO-GO for normal production use.** The repository contains useful implementation controls and UAT-era runbooks, but it lacks the retained privacy/legal, operational-ownership, alert-delivery, real-device UAT, production-configuration, backup-restore, and deployment-rollback evidence required by the checklist. Current client-storage behavior also creates an immediate stale-data and shared-device exposure risk.

## Evidence grading

- **A:** Two independent current repository sources corroborate the finding.
- **B:** Direct evidence in one current source/configuration/code artifact, without runtime proof.
- **C:** Absence/inference after a scoped repository search, or a stale/historical artifact not corroborated by current evidence.

Static code and configuration cannot prove a deployed control. `Pass` is therefore reserved for a complete static sub-domain; none of the assigned sub-domains meets that bar.

## Five highest P0 risks

1. **Authenticated data survives logout and can cross users on a shared device.** The worker has root scope, caches `/app` and later authenticated navigations/GET responses (`public/manifest.json:5-7`; `public/sw.js:1-10`; `public/sw.js:28-80`). The IndexedDB outbox stores full operation payloads under one global database/store (`resources/js/offline/outbox.js:6-18`, `resources/js/offline/outbox.js:46-60`). Logout invalidates only the server session and never clears either client store (`app/Http/Controllers/App/LoginController.php:51-60`). This can reveal customer/financial data to the next device user and replay stale content after privilege/tenant changes.
2. **Personal and employee location data is collected without a privacy/legal control plane.** A hidden component requests geolocation every minute (`resources/views/livewire/app/location-tracker.blade.php:1-25`), while Sentry browser tracing and error replay can run (`resources/js/app.js:1-15`). No privacy notice, lawful-basis/employee review, retention, rights process, vendor DPA/register, or browser-tracking consent evidence exists; the privacy story remains `ready-for-dev` (`bmad-output/stories/CG3.3.location-privacy-battery-controls.story.md:1-25`).
3. **Recovery is not proven and the optional logical backup is not durably stored by default.** The current restore log is empty (`docs/BACKUP_RESTORE.md:65-68`). The cron script writes under `/tmp/backups` (`scripts/backup.sh:8-10`, `scripts/backup.sh:21-36`), while persistence is only optional (`docs/BACKUP_RESTORE.md:11-23`). No RPO/RTO, independent backup, file/object-store restore, or full DR exercise exists.
4. **CI can report success after dependency/audit failures and does not build or certify the release artifact.** Composer/npm install fallbacks and both audit steps force success (`.github/workflows/ci.yml:36-44`, `.github/workflows/ci.yml:56-59`). CI omits type/E2E/secret/SAST/container/a11y/performance/build gates; Docker copies the repository and never builds JS (`Dockerfile:26-33`). A stale committed `public/build` can therefore ship while security gates appear green.
5. **A publicly named production deployment exists while normal Egyptian invoicing remains legally gated.** `railway.toml` names `https://jawla-production.up.railway.app` (`railway.toml:7-10`), but the signer is deliberately unsigned (`app/Providers/AppServiceProvider.php:62-74`) and the go-live runbook says Egypt must not launch until credentials, certificate signer and official preproduction validation are complete (`docs/GO_LIVE_READINESS.md:33-49`, `docs/GO_LIVE_READINESS.md:90-99`). Accidental real invoice use creates tax/compliance exposure.

### 1. Freeze the decision baseline and ownership

1. Product owner and technical owner select one versioned production scope/source-precedence document.
2. Reconcile five-vs-seven roles, beta-vs-production functionality, Forge/Render/Railway, Redis/queue, offline scope, storage, and ETA.

5. Obtain dated Finance/Sales/Purchasing/Warehouse/HR/Executive/Operations approval.

### 2. Contain the client-storage P0 before any real-data pilot

1. Change the worker to cache only versioned public static assets and a generic offline page; never cache authenticated HTML, API, Livewire, PDF, or error responses.
2. Restrict service-worker scope to the rep PWA if technically possible; ensure it cannot control `/admin`.
3. Namespace the IndexedDB outbox by company and user, minimize stored fields, define encryption/device-risk policy, and prevent another authenticated user from reading/replaying a prior user's queue.
4. On logout, deactivation, company/role switch and credential change, deliberately clear or quarantine authenticated caches/outbox according to the data-loss-safe policy.
5. In staging on one shared device: log in as rep A, visit pages and queue every operation type, logout, go offline, log in as rep B/company B, and verify no A HTML/payload/attachment/error is visible or replayed.
6. Repeat through service-worker update, failed install, stale cache, IndexedDB schema upgrade, app rollback, 401/419, duplicate retry and revoked-user scenarios. Retain screenshots, Cache Storage/IndexedDB exports, server receipts and defect/retest IDs.

### 3. Complete privacy/legal controls

6. Verify retention/deletion across DB soft deletes, location, activities, photos/signatures, Sentry/replay, Redis, logs, IndexedDB/cache, exports and backup expiry.

### 4. Make CI a real release gate

1. Delete all success-forcing fallbacks in `.github/workflows/ci.yml`.
2. On every PR from a trusted branch, run: `composer validate --strict`, deterministic Composer/npm installs, PHP syntax, Pint, Larastan/type checks, unit/integration tests on PostgreSQL, production asset build, critical browser/E2E suite, secret scan, SAST, dependency audit, SBOM, container scan, accessibility automation and performance-budget checks.

4. Build one immutable signed image/artifact; attach commit, lockfile hashes, SBOM and checksum; promote that same artifact to staging/production and retain the prior artifact.
5. Protect the production branch/environment with required reviews and company-owned deploy credentials.
6. Deliberately introduce one failing test, one high audit result and one build failure on a throwaway branch; prove each blocks merge/promotion and retain run links.

### 5. Prove observability and alert delivery

1. Add release/environment/request/correlation IDs to browser, backend and structured logs; set and review production log levels and redaction.
2. Configure durable restricted log ingestion and Sentry browser/server projects with browser-side field/replay masking and private source-map upload.

2. Test each migration against a production-volume copy/anonymized dataset; measure locks, validate old/new app compatibility, back up first, verify migration status and reconcile record/business-rule counts.

5. Deploy a tagged intentionally bad artifact, make health failure abort, then authorize and execute rollback to the retained previous artifact. Include compatible DB state, both replicas, Redis/queue, service-worker cache, IndexedDB/outbox and open sessions. Record recovery time and data loss against RTO/RPO.
6. Repeat recovery with the primary operator unavailable and include domain/DNS/certificate recovery. Resolve every finding before gate approval.

## Final release position

The safe decision from retained evidence is **NO-GO for normal production and NO-GO for real Egyptian invoicing**. A tightly controlled demo that uses synthetic data may proceed only if it is isolated from real company/personal data, uses demo accounts, clearly states that invoices are non-binding, and does not imply that the production gates above have passed. A real-data pilot still requires closure of client-cache/outbox isolation, privacy/legal review, company account control, alerting, restore/rollback drills, support ownership, and real-user UAT.

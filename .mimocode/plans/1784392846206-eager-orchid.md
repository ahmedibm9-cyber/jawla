# Verification Plan: ZATCA Phase 2 QR Codes on PDF Invoices

## Objective

Verify that QR codes render correctly on PDF invoices for:

1. **Saudi Arabia companies** with ZATCA Phase 2 (CSID + cryptographic stamp)
2. **Saudi Arabia companies** with ZATCA Phase 1 (no CSID, TLV fallback)
3. **Egypt companies** (simple format)
4. **Saudi companies without ZATCA enabled** (falls back to Egypt format)

## Current Implementation Summary

### Strategy Selection Logic (`InvoiceQrService::resolveStrategy`)

| Company Country | `zatca_enabled` | `zatca_csid` | Strategy Used                               |
| --------------- | --------------- | ------------ | ------------------------------------------- |
| SA              | true            | present      | `ZatcaPhase2Strategy` (cryptographic stamp) |
| SA              | true            | empty/null   | `ZatcaPhase1Strategy` (TLV QR)              |
| SA              | false           | —            | `EgyptQrStrategy`                           |
| EG / other      | —               | —            | `EgyptQrStrategy`                           |

### QR Format Specifications

- **ZATCA Phase 1**: Base64 TLV (tags 1-5: seller name, VAT#, timestamp, total+VAT, VAT amount)
- **ZATCA Phase 2**: Cryptographic stamp with UUID, hash chain, cryptographic signature
- **Egypt**: Simple `proforma_number|total` or `invoice_number|total` format

### PDF Integration

`PdfService::generateInvoice()` → `InvoiceQrService::generateForInvoice()` → `qrSvg()` → PDF

## Verification Approach

### Phase 1: Unit Tests for Strategy Classes

Create test file: `tests/Unit/Services/InvoiceQrServiceTest.php`

**Test Cases:**

1. **Saudi Phase 2** - Company: country=SA, zatca_enabled=true, zatca_csid=present
   - Verify strategy = ZatcaPhase2Strategy
   - Verify QR contains TLV + cryptographic stamp
   - Verify QR is valid Base64

2. **Saudi Phase 1** - Company: country=SA, zatca_enabled=true, zatca_csid=null
   - Verify strategy = ZatcaPhase1Strategy
   - Verify QR is valid TLV Base64
   - Decode TLV and verify 5 tags present

3. **Saudi No ZATCA** - Company: country=SA, zatca_enabled=false
   - Verify strategy = EgyptQrStrategy
   - Verify QR = simple format

4. **Egypt Company** - Company: country=EG
   - Verify strategy = EgyptQrStrategy
   - Verify QR = simple format

5. **Proforma Invoices** - Same strategy selection logic applies

### Phase 2: PDF Integration Tests

Create test file: `tests/Feature/PdfQrCodeTest.php`

**Test Cases:**

1. **Generate Invoice PDF** for Saudi Phase 2 company
   - Assert PDF generated successfully
   - Extract QR code from PDF (if possible) or verify QR SVG in HTML
   - Verify QR data matches expected TLV + stamp format

2. **Generate Invoice PDF** for Saudi Phase 1 company
   - Verify QR is TLV Base64 (Phase 1)

3. **Generate Invoice PDF** for Egypt company
   - Verify QR is simple format

4. **Generate Proforma PDF** for each scenario
   - Verify same strategy selection applies

5. **Generate Receipt PDF** (payment)
   - Verify receipt QR uses simple format regardless of company

### Phase 3: Manual Verification Checklist

For production-like testing:

1. **Create test companies in database:**
   - Saudi Phase 2: `country=SA, zatca_enabled=1, zatca_csid=test-csid, zatca_secret=test-secret`
   - Saudi Phase 1: `country=SA, zatca_enabled=1, zatca_csid=null`
   - Saudi No ZATCA: `country=SA, zatca_enabled=0`
   - Egypt: `country=EG`

2. **Generate invoices via SalesFlow (REP PWA)**
   - Verify QR appears on PDF
   - Scan QR with ZATCA validator (if available)

3. **Edge Cases:**
   - Company with missing `name_ar` (should still generate QR)
   - Company with missing `tax_number` (should handle gracefully)
   - Invoice with zero VAT (should still generate valid TLV)

## Risk Areas to Monitor

1. **ZATCA Phase 2 Implementation** - `ZatcaPhase2Strategy` may need actual cryptographic signing (currently appears to be placeholder)
2. **Missing `zatca_secret`** - Phase 2 requires secret for signing; verify handling
3. **PDF Library** - mPDF must render QR SVG correctly (size=100)
4. **Arabic Text in TLV** - UTF-8 encoding must be preserved in Base64
5. **Date/Time Format** - ISO 8601 with timezone for ZATCA compliance
